# Strategic Opening Coach

Today, the Study screen teaches lines by drilling moves with arrows + (occasional) move explanations. There's no answer to *"what am I trying to accomplish?"* and when the opponent plays an off-book move, the player is left stranded.

This plan adds three layers of strategic context — all AI-generated by default, with dev override.

## What you'll see in the app

1. **Goals panel** (collapsible, above or beside the move history in `StudySidebar`):
   - Opening name + 2–4 bullet "key ideas" (e.g. *"Control the center with e4/d4"*, *"Target the f7 square"*, *"Develop bishop to c4 aiming at the weak square"*).
   - Key squares chip row (e.g. `e5 · f7 · d5`).
   - Typical plans for your side (1–2 short sentences).
   - Always visible while studying — persistent reminder of the "point".

2. **Per-move purpose**: Every move (yours and opponent's) gets a one-line *why*, e.g. `Bc4 — eyes f7, prepares short castle`. Surfaces inline in the existing explanation bubble (replaces/augments `moveExplanations`). Player moves get a stronger tagline; opponent moves explain their intent so you understand what to respond to.

3. **Deviation coach**: When the opponent plays a move that isn't in the learned tree, instead of just "wrong line", show a panel:
   - *"Off book. Remember the plan:"* + the 2–3 most relevant goals from the opening.
   - *"Aim for:"* a generic principle (e.g. *"complete development, castle, contest the center"*).
   - Optional Stockfish suggestion (Pro): top move in the new position with one-line rationale.

## Authoring model

- **Default = AI generated** via Lovable AI (Edge Function `generate-opening-coaching`) using `google/gemini-2.5-flash` with structured output (zod schema). Generated once per (opening, variation, line) and cached in a new Supabase table.
- **Dev override**: extends the existing dev-edit pattern (your `xinya.vivian@me.com` flow + `move_explanations` table) — you can edit any goal/purpose inline; edits win over AI output.
- Generation triggered lazily: when a line is first opened, if no cached coaching exists, fire-and-forget an Edge Function call; show a subtle "Generating insights…" shimmer in the goals panel. Subsequent visits load instantly from cache.

## Data model

New table `opening_coaching`:
- `opening_id`, `variation_id`, `line_index` (composite key)
- `goals jsonb` — `{ summary, keyIdeas[], keySquares[], typicalPlans[] }`
- `move_purposes jsonb` — `{ [moveIndex]: { short, long } }`
- `deviation_hints jsonb` — `{ generalPrinciples[], aimFor }`
- `source text` — `'ai' | 'dev'` (per-field overrides stored in existing `move_explanations` continue to take priority for that move)
- `generated_at`, `model` for observability

RLS: read open to authenticated users; write restricted to dev email (matches your existing `redeem_codes` pattern). The Edge Function uses the service role to write AI output.

## Detection of "off book"

`Study.tsx` already knows the expected next move from the tree. When sparring/practice mode receives an opponent move that's not in the tree at all (vs. a wrong player move which already has feedback), set `isOffBook=true` and render `<DeviationCoach />` in the sidebar instead of the normal explanation bubble. Player can then either reset or "continue freestyle" (board stays playable, Stockfish suggests best moves if Pro).

## Out of scope (deliberate)

- No changes to the drill/post-game flow — only the opening study Study screen.
- No new payment tier; deviation Stockfish suggestion reuses existing `canAnalyze`/Pro gating.
- No retroactive backfill — coaching generates on first visit per line.
